**Manuscript:** *Bayesian Generalized Nonlinear Models Offer Basis-Free SINDy with Calibrated Model Uncertainty* (`paper_icml/main.tex`)

---

## 1. Summary

The manuscript proposes a systematically tuned Bayesian Generalized Nonlinear Model (BGNLM) framework built on `FBMS` (`gmjmcmc.parallel`) for basis-free discovery of governing ordinary differential equations (ODEs). Key methodological refinements over an earlier workshop prototype include unknown-variance Jeffreys-BIC priors, a complexity-penalized model prior ($r = N^{-1}$), disabling linear-combination projection mutations ($p_{\text{proj}} = 0$), radian-scaled physical operators, a low-dimensional collinearity-check patch in `FBMS`, and relative $L_2$-energy pruning ($\tau = 0.025$) of the Median Probability Model (MPM). The authors evaluate 13 methods across 109,192 synthetic runs (12 ODEs) and 2,600 "real-world empirical" runs (5 datasets) using hierarchical Linear Mixed-Effects Models (LMMs).

While the core BGNLM tuning insights are valuable and the mixed-effects evaluation pipeline is well-engineered, **a thorough code-and-data audit reveals severe discrepancies between what the paper claims and what the code actually executed**. Specifically: (i) all 5 "real-world empirical datasets" are actually synthetic `deSolve::ode` integrations with Gaussian noise; (ii) `SR_PySR` and `SR_Operon` did not run native PySR or PyOperon, instead falling back to a static-dictionary OMP + random-mutation heuristic; (iii) `UQ_SINDy` contains a coefficient scale-mismatch bug and is not Hirsh et al. (2022); (iv) `SINDy_PI_Rational` is an explicit `Poly(2)`+rational STLSQ baseline rather than implicit SINDy-PI; (v) Experiment 1 evaluates only clean states with additive derivative noise, omitting errors-in-variables state noise; and (vi) several empirical explanations (`N=2500` drop, `Yeast` $R^2_{\text{traj}} \approx 0$, `sys01` upper bound) contradict the actual aggregated data.

---

## 2. Strengths

1. **Genuine Structural Pitfall Fixes in `FBMS`**: Disabling projection mutations ($p_{\text{proj}}=0$), replacing degree-scaled trigonometry with radian/rational physical transforms (`R/03_fbms_wrappers.R`), freeing $\sigma_j^2$, and patching `FBMS:::check.collinearity` for low-dimensional ($m \in \{2,3,5\}$) state spaces are concrete, well-motivated fixes for dynamical systems.
2. **Principled Statistical Evaluation**: Using hierarchical LMMs (`lme4`/`lmerTest`) with crossed/nested random effects (`System` and `System:Seed_ID`), Dunnett multiplicity adjustment, Nogueira stability $\hat{\Phi}$, and variance decomposition (ICC) is far more rigorous than standard mean-table comparisons in SINDy/SR benchmarks.
3. **Strong Polynomial & 5D Lorenz-96 Recovery**: Against well-configured predefined-basis baselines (`BGLM_Oracle_Basis`, `BGLM_Poly_Basis`, `SINDy_STLSQ_Oracle`), `BGNLM_Full_Tuned` achieves impressive FDR control ($0.102$ overall, $0.018$ on 5D Lorenz-96) and well-calibrated 95% intervals ($92.6\%$ coverage).

## 3. Major Weaknesses

### W1. Experiment 2 ("Real-World Empirical Datasets") Uses Synthetic ODE Simulations, Not Empirical Data
Section 5 (lines 331–342), Table 7 (`tab:real_spec`), and the Abstract claim Experiment 2 benchmarks 5 canonical *real-world empirical datasets* ("when true governing physics are unknown or approximate", citing Odum 1953, Gause 1934, Schmidt & Lipson 2009, Schoukens & Noël 2017, Richard et al. 1996). However, `scripts/download_real_data.R` reveals that **every single CSV in `data/real_world/` is synthetically generated by integrating an idealized ODE via `deSolve::ode(..., method="lsoda")` and adding i.i.d. Gaussian noise**:
- `prepare_lynx_hare` (lines 18–54) defines the historical 1900–1920 `hare_core` and `lynx_core` vectors and **never uses them**, instead integrating Lotka–Volterra ($\alpha=0.55, \beta=0.028, \delta=0.026, \gamma=0.84$, $N=201$) + $\mathcal{N}(0, 0.20^2)$.
- `prepare_gause_paramecium` (lines 59–81) integrates Holling Type-II ($N=71$) + $\mathcal{N}(0, 0.015^2)$ / $\mathcal{N}(0, 0.012^2)$.
- `prepare_schmidt_pendulum` (lines 86–105) integrates a damped pendulum ($N=500$) + $\mathcal{N}(0, 0.008^2)$ / $\mathcal{N}(0, 0.015^2)$.
- `prepare_cascaded_tanks` (lines 110–138) integrates Torricelli $\sqrt{x_1}, \sqrt{x_2}$ ($N=1024$) + $\mathcal{N}(0, 0.01^2)$.
- `prepare_yeast_glycolysis` (lines 143–166) integrates Selkov–Hill ($N=300$) + $\mathcal{N}(0, 0.008^2)$.

Representing synthetic ODE trajectories as "real-world empirical datasets" is a major factual error that invalidates claims about model misspecification on real data.

### W2. `SR_PySR` and `SR_Operon` Did Not Run Native PySR or PyOperon
Section 3.1 (line 182) and Section 1 (line 64) describe `SR_PySR` and `SR_Operon` as genetic-programming symbolic regression (`PySR` with Pareto knee selection `best`, `PyOperon` with Levenberg–Marquardt refinement + MDL, tree depth 4, max size 25). In `python/run_sr_pysindy.py` (lines 290–298):
- Native `PySRRegressor` and `pyoperon.sklearn.SymbolicRegressor` are gated behind `PYSR_USE_JULIA == "1"` and `PYOPERON_NATIVE == "1"`. Neither `scripts/run_remote_server.sh` nor `R/04b_sr_baselines.R` sets these environment variables.
- Furthermore, the native branches (lines 324–325, 347–348) return `intercepts_out.append(0.0)` and `coefs_out.append({})`, which would cause `R/04b_sr_baselines.R` (`predict_rhs_fn`, lines 125–140) to predict identically zero derivatives (`R2_traj = 0.0`). Because `SR_PySR` and `SR_Operon` report `R2_traj = 0.703` and `0.725` with runtimes of `4.41 s` and `5.92 s`, **100% of reported SR runs executed the internal fallback `fit_evolutionary_pareto_sr()`** (lines 114–259).
- That fallback is **not** genetic programming over arbitrary expression trees: it is an OMP-guided greedy forward + random single-atom mutation beam search (beam width 8, max 6 terms) over a **static precomputed dictionary** (`generate_candidate_atoms()`, lines 26–88), where `operon_mdl`'s `least_squares(..., method="lm")` simply re-solves a linear least-squares problem `X_s @ b - y`. Comparing BGNLM against this custom static-library heuristic while labeling the baselines `PySR` and `PyOperon` is unfair and inaccurate.

### W3. Misrepresented & Buggy SINDy Baselines (`UQ_SINDy` Scale Bug, `SINDy_PI_Rational`)
1. **`UQ_SINDy_Oracle` / `UQ_SINDy_Poly` (`R/04_sindy_baselines.R`, lines 205–264)**:
   - Described in Section 3.1 as "Bayesian bootstrap UQ-SINDy (Fasel et al., 2022; Hirsh et al., 2022)". In reality, it does not implement Hirsh et al.'s (2022) Bayesian spike-and-slab/Laplace UQ-SINDy (nor Dirichlet Bayesian bootstrap); it is frequentist bootstrap bagging ($B=80$, 85% resample with replacement) of STLSQ.
   - **Critical scale-mismatch bug (line 213)**: `lam_base <- max(0.03, median(abs(fit_base$coefs[fit_base$active])) * 0.25)` computes a threshold from **unstandardized** OLS coefficients `fit_base$coefs` (e.g., $\rho=28, \sigma=10$ in Lorenz-63, yielding `lam_base` up to $7.0$!), and then passes `lam_base` into `stlsq_fit_single(..., lambda = lam_base)` where line 45 thresholds **standardized** coefficients `abs(w_std) >= lambda` (typically $\le 1$). Conversely, on small-coefficient equations, `lam_base = 0.03` is far too permissive, explaining the severe FDR inflation (`0.406–0.490`) and collapsed `R2_traj` (`0.569–0.578`) relative to `SINDy_STLSQ_Oracle` (`0.758`).
2. **`SINDy_PI_Rational` (`R/04_sindy_baselines.R`, lines 96–134)**:
   - Described as SINDy-PI (Kaheman et al., 2020), which solves implicit ODEs $f(\boldsymbol{x}, \dot{\boldsymbol{x}}) = 0$ via parallelized LHS-term sweeping so rational denominators become polynomial cross-terms $\dot{x}_j q(\boldsymbol{x}) = p(\boldsymbol{x})$.
   - Instead, `build_sindy_pi_rational_library` builds an **explicit** static dictionary concatenating `Poly(max_deg=2)` and 6 fixed rational templates (`1/(1+|x|)`, `x/(1+|x|)`, `1/(1+x^2)`, `x^2/(1+x^2)`, `xi*xj/(1+|xi|)`, `xi*xj^2/(1+xj^2)`). Because it truncates polynomials at degree 2 (`max_deg = 2L`, line 104), it omits $x_1^3$ and $x_1^2 x_2$ and fails on Group A systems (Duffing, Van der Pol, Brusselator), which is an artifact of the wrapper rather than SINDy-PI.

### W4. Experiment 1 Noise Model: Clean States + Derivative Noise Only (No Errors-in-Variables)
Although `R/01_ode_simulators.R` implements `"state_noise"` and `"iwsm_absolute"`, and `config/benchmark_grid.yaml` defines `state_noise_eta`, `scripts/generate_manifest.R` (line 72) hardcodes `noise_regime = "derivative_snr"` for all 109,200 tasks. Thus:
- In Experiment 1, $\boldsymbol{X}_{\text{train}}$ is **noiseless** and sampled non-contiguously from `lsoda`, while i.i.d. Gaussian noise is added directly to finite-difference derivatives $\boldsymbol{Y}_{\text{train}}$.
- Consequently, Experiment 1 never evaluates **errors-in-variables bias** in nonlinear transforms $g_k(\boldsymbol{X} + \boldsymbol{\nu})$ or numerical differentiation noise amplification—precisely the regime where weak-form SINDy and smoothing-based differentiation matter most. The manuscript must explicitly state that Experiment 1 isolates additive derivative noise with exact state observations, and distinguish this from noisy-state differentiation in Experiment 2.
- Additionally, in Experiment 2 (`R/10_real_data_experiments.R`, lines 126–130), differentiation (`sgolay_spline` or `tvregdiff`) is applied to the **entire** time series (train + OOD test) *before* the temporal split, leaking future trajectory smoothness across the train/OOD boundary. Moreover, `estimate_derivatives_tvregdiff` (lines 519–553) is an *ad hoc* tridiagonal IRLS smoother on central differences (`solve(M, du)` with fixed $\alpha=10^{-2}$) rather than Chartrand's (2011) anti-differentiation integral formulation.

### W5. Inaccurate Dynamical Explanations & Missing Analyses
1. **Why `BGNLM_Full_Tuned` Drops at $N=2500$ (Line 308)**: The paper attributes the F1 drop from $0.883$ ($N=500$) to $0.760$ ($N=2500$) to "$r = N^{-1}$ becoming slightly conservative on weak non-polynomial terms like $0.2\sin(x_1)$". Checking `synth_cell_summary_stability.csv` and `synth_results.csv` shows the **opposite**: as $N$ grows from $500 \to 2500$, `Mean_TPR` dips only modestly ($0.880 \to 0.813$), whereas **`Mean_FDR` more than triples ($0.0628 \to 0.2138$)**, with Group B falling from $0.842$ to $0.629$. Inspection of discovered atoms at $N=2500$ (e.g., `sys08`, `sys10`, `sys11`) shows BGNLM selecting multi-term polynomial/composite Taylor surrogates (e.g., `x1, x1^3, sqrt(x1)*x1, ^(x1)` instead of `sin(x1)`). Under Jeffreys-BIC, the likelihood scales as $O(N)$ while the penalty scales as $O(\log N)$; at $N=2500$, the sharper likelihood surface traps fixed-budget GMJMCMC ($N_{\text{MCMC}}=500, P=12$) in dense surrogate local modes.
2. **Why `Yeast Glycolysis` Yields $R^2_{\text{traj}} \approx 0$ (Lines 385, 395)**: The paper blames "stiff phase-drift in noisy biochemical oscillations". In fact, checking `data/real_world/yeast_glycolysis_nadh.csv` and `prepare_yeast_glycolysis` ($v_0=0.75, c_1=0.15, c_2=1.80, c_3=0.20, c_4=0.85$) reveals the trajectory is a **damped spiral** that converges to its stable equilibrium $(x_1^*, x_2^*) \approx (0.763, 0.927)$ before the 70% cutoff ($t \approx 21$). In the held-out window $t \in [21, 30]$, clean state variation ($x_1 \in [0.742, 0.782]$) is comparable to observation noise ($\sigma=0.008$), making `R2_test_ood = 0.000` and `R2_traj = 0.000` for **all 13 methods**, while `R2_test_in` is $0.947$.
3. **Why `sys01` Fails Across Methods (Line 270)**: First, the text states `F1 <= 0.267`, whereas `BGNLM_Full_Tuned` actually achieves `Mean_F1 = 0.3303` (`SR_Operon = 0.2672`, `BGLM_Oracle_Basis = 0.0372`). Second, the root cause is the train/OOD split in `R/01_ode_simulators.R` (line 630): `idx_interior` is $(0.05 T, 0.99 T) = (1, 19.8)$, so the entire fast transient of `sys01` ($t \in [0, 1]$) is placed in `idx_ood_early`, leaving training samples strictly on the dead equilibrium ($x_1 \approx 0, x_3 \approx 0, x_2 \approx \text{const}$).
4. **`BGNLM_Hybrid_Poly` vs. `BGNLM_Full_Tuned` Mechanism (Line 249)**: Feeding $\mathcal{P}_2(\boldsymbol{X})$ as base covariates with `keep.org = TRUE` assigns quadratic/bilinear terms complexity $c=1$ (same as $x_i$), saturating `pop.max = 20` from generation 0 and allowing depth-2 compositions on top of quadratic features (e.g., $\sin(x_1 x_2)$), which inflates Group B FDR from $0.225$ to $0.412$ (and up to $0.691$ on `sys10`).
5. **Canonicalizer Algebraic Blind Spot on Rational Identities**: On `sys11_goodwin_mm`, `BGNLM_Full_Tuned` frequently discovers `hill_2(x3)` ($= x_3^2/(1+x_3^2)$) plus an intercept $1$, which is algebraically identical to $1/(1+x_3^2)$ since $1 - x_3^2/(1+x_3^2) = 1/(1+x_3^2)$ (and similarly $1 - 1/(1+x_3) = x_3/(1+x_3)$). Because `extract_canonical_atoms()` strips intercepts and does not reduce $1 - f(x)$ rational identities, exact discoveries are penalized as simultaneous false positives and false negatives, artificially depressing Goodwin F1 ($0.570$). Furthermore, `sys08` at $N=2500$ outputs a malformed canonical token `eq1::^(x1)` that requires debugging in `R/05_symbolic_canonicalize.R`.

## 4. Minor Issues & Verification Audit

1. **Table 6 (`tab:systems_spec`)**:
   - **Sys 10 (Thomas Attractor, line 473)**: $\dot{x}_i = \sin(x_{i+1 \bmod 3}) - bx_i$ for $i=1,2,3$ has a 1-based indexing error: when $i=2$, $(2+1)\bmod 3 = 0 \implies x_0$. Write $\sin(x_{(i \bmod 3) + 1})$ or list the three equations explicitly.
   - **Sys 11 (Goodwin MM, line 474)**: `systems_config.yaml` and `01_ode_simulators.R` include Hill exponent `p = 2.0` (omitted from Parameters column) and implement $K_m + |x_3|$ in `01_ode_simulators.R` (line 399), whereas Table 6 writes $K_m + x_3$ (equivalent only for $x_3 > 0$). Also, `evaluate_basis_atom()` in `R/02_basis_builders.R` omits `abs()` protection for denominators `1+x`.
   - **Intercept Omission Across Systems**: Systems 3 ($b=0.2$), 7 ($a=1.0$), 8 ($c=0.4$), and 12 ($F=8.0$) contain constant intercept terms that are **omitted** from `ground_truth_atoms` (`R/01_ode_simulators.R`), and `extract_canonical_atoms(..., include_intercept = FALSE)` ignores all intercepts. Thus missing $F=8.0$ or adding spurious constants is never penalized in F1/FDR/Exact Recovery. This must be explicitly disclosed in Section 3.2.
2. **Hyperparameter & Calibration Discrepancies**:
   - **Generations $P$**: Lines 119 & 134 (Algorithm 1) report $P=15$, whereas `config/best_bgnlm_params.yaml` (line 13) and the benchmark runs used `P_generations = 12`.
   - **Calibration Slice (Line 146)**: Claims calibration ran on *Lorenz-63, Rössler–Lorenz Hybrid, and Michaelis–Menten Goodwin* at $\sigma \in \{0.05, 0.25\}$. `R/07_tuning_engine.R` (lines 119–120) and `results/aggregated/tuning_runs_raw.csv` actually ran *Lorenz-63, Rössler–Lorenz Hybrid, and Lotka–Volterra* (`sys04_lotka_volterra`) at $\sigma \in \{0.01, 0.25\}$.
   - **$L_2$-energy pruning threshold**: `0.025` in `BGNLM` vs. `0.02` in Python SR (`run_sr_pysindy.py` line 359) vs. `1e-4` in `BGNLM_IWSM_Untuned` vs. none in `SINDy`.
3. **Table 2 (`tab:synth_regimes`) Omission**: `UQ_SINDy_Oracle` is missing from Table 2 (only 12 of 13 methods are listed).
4. **STLSQ CV Split (`R/04_sindy_baselines.R`, line 71)**: `rep(seq_len(k_folds), length.out = n)` uses systematic interleaved folds rather than contiguous temporal blocks or random splits.
5. **RK4 Exogenous Input Interpolation (`R/06_metrics_consistency.R`, lines 195–201)**: On `Cascaded Water Tanks`, `X_inputs` inside RK4 uses nearest-neighbor lookup `which.min(abs(times - t))`, creating step-discontinuous forcing at RK4 intermediate stages instead of linear/spline interpolation (`approx()`).
6. **Table 1 / Appendix Consistency**: All LMM numbers in text match `table_mixed_effects_synth.tex`, `table_mixed_effects_real.tex`, and `table_mixed_effects_icc.tex`, and `BGLM_Overcomplete` completion (`7736/8392`, 656 failed + 8 timed out) matches the text.

## 5. Specific, Actionable Fixes

1. **Fix Experiment 2 Data Provenance or Reframing (Critical)**: Either replace the 5 synthetic CSVs in `scripts/download_real_data.R` with genuine empirical measurements (actual 1900–1920 Hudson Bay pelts, Veilleux microcosm counts, Schmidt–Lipson pendulum video data, Schoukens cascaded tanks data, Danø/Richard yeast NADH fluorescence) and re-run Experiment 2, **or** explicitly rebrand Experiment 2 as a *Quasi-Empirical State-Noise & Numerical-Differentiation Benchmark* simulating literature ODEs under noisy observation and temporal CV. Adjust `prepare_yeast_glycolysis` parameters into the oscillatory limit-cycle regime (or report phase-invariant attractor / single-step metrics alongside $R^2_{\text{traj}}$).
2. **Run Genuine `PySR` and `PyOperon` (Critical)**: Since `pysr` and `pyoperon` are installed in `.venv`, set `PYSR_USE_JULIA=1` and `PYOPERON_NATIVE=1`, fix `python/run_sr_pysindy.py` + `R/04b_sr_baselines.R` so native `PySRRegressor` / `pyoperon` predictions (`predict()`) and fitted constants are passed directly into `predict_rhs_fn` (instead of empty `coefs_out={}`), and re-run `SR_PySR` and `SR_Operon`. Alternatively, rename them accurately to `SR_StaticPool_OMP_Pareto` and `SR_StaticPool_MDL`.
3. **Fix `UQ_SINDy` & `SINDy_PI_Rational` Baselines (Critical)**:
   - In `R/04_sindy_baselines.R` line 213, fix the unstandardized-vs-standardized threshold mismatch (use the CV-selected standardized $\lambda^*$ directly across bootstrap replicates, or implement genuine Bayesian spike-and-slab/Laplace UQ-SINDy via `pysindy`/`PyMC`).
   - Either implement true implicit SINDy-PI (LHS sweeping with degree-3 + rational terms) or rename `SINDy_PI_Rational` to `SINDy_Explicit_RatPoly2` and include degree-3 polynomials.
4. **Clarify Noise Regimes & Add State-Noise Slice**: Explicitly state in Sections 2.1 and 4.1 that Experiment 1 uses noiseless states $\boldsymbol{X}$ with additive derivative noise, and run at least a focused synthetic ablation under `noise_regime = "state_noise"` (already implemented in `R/01_ode_simulators.R`!) to demonstrate robustness to errors-in-variables bias.    - Lines 385, 395: Correct the `Yeast` $R^2_{\text{traj}} \approx 0$ explanation (damped spiral convergence to equilibrium prior to the OOD window).
   - Lines 119, 134: Change $P=15$ to $P=12$ (matching `best_bgnlm_params.yaml`).

   - Table 2: Add the missing `UQ_SINDy_Oracle` row.
   - Debug `^(x1)` canonicalization and add $1 - x^2/(1+x^2) \equiv 1/(1+x^2)$ rational-complement normalization in `R/05_symbolic_canonicalize.R`.
